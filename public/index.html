This is a planning tool, not a bill. Every catalog entry links to its source. Prices are a dated snapshot; OpenRouter can refresh its public catalog on demand.
How requests, reasoning, and caching work
Total mode estimates the entered request count. Calling-rate mode multiplies the rate by active hours and estimate days, then adds retry overhead. Total-output mode already includes thinking; visible-output mode adds your assumed reasoning tokens. There is no invented effort multiplier.
Cache-read and write percentages partition the base input. Token rates, whole-request context tiers and known dated promotions are resolved before billing. Context limits include input, tool-result tokens and all output.
What this estimate includes and excludes
Includes configured token, native search/retrieval, container, storage, route request, and custom tool fees. Taxes, credit purchase fees, regional premiums, reserved throughput, provider rate-limit capacity, minimum cache lengths and unentered tool overhead are excluded. Retries assume the same average workload. A 30-day equivalent is a normalization, not an additional charge.
Pro reasoning mode may aggregate extra model work; enter actual billed totals. Batch tool compatibility is not modeled, so use Standard when enabling native tools. Remaining free allowances must be entered manually and are not separately granted to every model you deploy.
Provider-specific caveats
Google thinking controls use their own settings, so generic effort filtering does not claim Gemini support. Google 4 uses implicit caching only. Claude cache writes use short/long retention and Haiku 5.5 reprices the full prompt above 100K input. Mistral native tool rates need a custom fee because fresh official rates were unavailable. OpenRouter variants are distinct routes, and conditional price rules that cannot be safely interpreted are excluded.
